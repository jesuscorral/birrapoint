# 0020 - Keycloak deploy service-account client for post-deploy client reconciliation

**Status:** Superseded by ADR-0022
**Date:** 2026-09-27

## Context

Keycloak imports the realm only on first start, and the realm lives in Neon, which survives
`teardown.ps1`. A recreated Container Apps environment gets a new random domain, so the stored
`birrapoint-spa` client rejects the new web URL (`Invalid parameter: redirect_uri`). `deploy.ps1`
therefore reconciles the client's URLs after each full run. Doing it as the bootstrap admin was
fragile (Keycloak marks that account temporary and recommends removing it) and far too powerful.

## Decision

1. **Confidential client `birrapoint-deploy`** in the `birrapoint` realm, service accounts only,
   holding `realm-management` `view-clients` + `manage-clients` — no `master` rights, no user
   management.
2. **Secret generated by Terraform** (`random_password.deploy_client_secret`), passed to Keycloak
   as `DEPLOY_CLIENT_SECRET` for the import (via Key Vault/Dapr, ADR-0021); the production image
   strips the local fallback.
3. **`deploy.ps1` uses `client_credentials`** as this client. If rejected (realm imported before
   the client existed, or secret drift), it uses the bootstrap admin **once** to create/repair the
   client and its two roles; if that fails too, it stops with manual instructions.
4. **URLs are merged**: the current web URL is added to redirect URIs, web origins and
   post-logout URIs; only this app's own stale Container Apps domains are removed; manual URIs
   survive; nothing is written when already in sync (order-insensitive comparison).

## Consequences

- Deploys stop depending on the bootstrap admin once the client exists.
- The credential is narrower but still broad **indirectly**: realm-wide `view-clients` +
  `manage-clients` can read `birrapoint-api-admin`'s secret (which can manage users), regenerate it,
  or add redirect URIs to `birrapoint-spa`. It adds no exposure for holders of the Terraform state,
  but it must **never be copied into CI**; `deploy.yml` (`-AppsOnly`) does not need it. Narrowing it
  with Keycloak fine-grained admin permissions v2 is T141.
- The repair enforces exactly the two roles.
- Local development imports the same client with a local-dev secret.
